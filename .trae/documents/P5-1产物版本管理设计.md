## 1. Context 与目标

P5-0 已交付统一 StorageBackend + /artifacts 读取。但当前 `overwrite` 模式直接覆盖主 key，历史内容不可回溯。版本管理解决：**同一 rel_path 每次写入归档为历史版本，可回溯任意版本、对比两个版本差异**。

**目标**：
- 版本链：同一 key 每次写入归档 v1..vN（最新 = 主 key），超上限自动淘汰最旧。
- 回溯：`GET /artifacts/{task_id}/{path}?version=N` 读任意历史版本。
- 对比：`GET /artifacts/{task_id}/{path}/diff?from=N&to=M` 返回行级 diff（含资源约束）。
- 兼容锚点：**默认关闭**（`ARTIFACT_VERSIONS_ENABLED=false`）且**纯透传**，行为与 P5-0 零漂移。

## 2. 现状锚点（已核对 config / local.py / s3.py / fs.py / artifacts.py / repos.py）
- 写：`fs_write` → `backend.put(key, data, mode)`；`overwrite` 直接覆盖主 key。
- 读：`/artifacts/{task_id}/{path}`（can_view）流式；list 排除 `_tmp`。
- 元数据：`TaskNode.output` 承载产物元数据（预留）；`ArtifactMeta` 含 checksum/mode/run_id/producer_role。
- 审计：产物操作写 AuditLog（task_id+trace_id）；`write_audit` 已就绪。
- 配置：`STORAGE_*/S3_*/ST_*` 已就绪；`repos.list_old_tasks`（生命周期）已就绪。

## 3. 方案选型（克制，不侵入 Agent/工具协议）

在现有后端之上加 **VersionManager 包装层**，**不改 StorageBackend 契约、不改 fs 工具入参协议、不改 Agent**；版本能力由「开关 + API + 包装层」叠加。

```
fs 工具 / /artifacts API
        │
        ▼
app/storage/versioning.py  VersionManager
        │  版本链：DB 状态机 + _v 空间归档 + 淘汰/巡检/对账
        ▼
StorageBackend (local / s3，逻辑不变)
```

- 版本命名空间（不污染产物列表，沿用 `_tmp` 排除模式）：
  `artifacts/_v/{task_id}/{rel_sha1}/v{n}`（`rel_sha1 = sha1(rel_path)[:12]`，定长防转义）。
- **版本语义**：v1..vN 递增；最新版本 = 主 key；读 `?version=N` 从 `_v` 取；不传 = 主 key。
- **🔴4 关闭态 = 纯透传**：`ARTIFACT_VERSIONS_ENABLED=false` 时 VersionManager 直通底层 backend，**不捕获、不修改返回值、不加分支语义**，行为与 P5-0 逐字节一致。

## 4. 关键设计

### 4.1 配置（默认全关，兼容锚点）
```
ARTIFACT_VERSIONS_ENABLED: bool = False    # 默认关：overwrite 行为与 P5-0 零漂移
ARTIFACT_MAX_VERSIONS: int = 5             # 每 rel_path 保留最大版本数（≥1）
ARTIFACT_VERSION_SIZE_LIMIT: int = 2 * 2**20   # ⭐5 大文件版本阈值（2MB），超限不自动归档
ARTIFACT_DIFF_MAX_SIZE: int = 2 * 2**20    # 🔴6 diff 文件大小上限（2MB），超限返回 too_large
ARTIFACT_DIFF_PREVIEW_LINES: int = 200     # 🔴6 diff 预览行数上限
ARTIFACT_PENDING_TTL: int = 3600           # 🔴1 pending 记录巡检阈值（秒）
ARTIFACT_RECONCILE_INTERVAL: int = 86400   # ⭐4 存储与 DB 对账周期（秒，默认每日）
```
- 关：VersionManager 纯透传；`no_overwrite`/`new` 不受开关影响，行为始终与 P5-0 一致（🔴4）。

### 4.2 版本状态机（🔴1：存储+DB 双系统收敛）
`artifact_versions` 新增 `status` 字段：`pending → available`（失败 → `failed`）。

**写入强制顺序**（每步失败处理明确）：
1. **DB 插入**版本记录 `status=pending`（含 version、归档 key、sha256 占位）；
2. **存储归档**：当前主 key → `_v/.../v{n}`（大小 ≤ `ARTIFACT_VERSION_SIZE_LIMIT` 才归档，超限直接跳过归档 → 直接置 available 且仅登记「未归档」标记）；
3. **写主 key**（原 put 原子逻辑）；
4. **DB 更新** `status=available` + 填 sha256/size + 淘汰超 `ARTIFACT_MAX_VERSIONS` 的最旧 available 版本（删 `_v` 对象 + 删行）。

失败兜底：
- 步骤 2/3 失败 → 记录置 `failed`（主 key 未动则视为未变更）；`failed` 记录**不参与幂等比对、不计入版本号**。
- **后台巡检**（复用 GC 协程）：扫描 `pending` 超过 `ARTIFACT_PENDING_TTL` 或 `failed` 的记录 → 删 `_v` 归档对象 + 删行，写审计。
- 幂等收敛仅基于最新 `available` 记录（🔴1/⭐1：**内容 sha256 + run_id 双重匹配**才判定重复，不产生新版本）。

### 4.3 并发版本号（🔴2：行级排他锁 + 原子递增）
- 锁粒度：事务内对 `(task_id, rel_path)` 行取**排他锁**（`SELECT ... FOR UPDATE`）后再计算版本号。
- 版本号生成：DB 原子 `UPDATE artifact_versions SET version = version + 1 WHERE task_id=? AND rel_path=? AND version=(SELECT max(version)...) RETURNING version`（首写插入 v1），确保并发唯一递增。
- 归档 key **携带版本号**（`v{n}`），并发下不会同名覆盖。
- 测试必须覆盖多协程并发 overwrite：断言版本号唯一、最终内容 = 最后写入值。

### 4.4 版本空间路径安全（🔴3）
- 所有版本 key 生成**必须**经 `normalize_artifact_key` 的统一闸口（内部走 `_v` 子空间：`normalize_artifact_key(task_id, f"_v/{rel_sha1}/v{n}", allow_tmp=True)` 思路扩展），强制限定 `artifacts/_v/` 前缀；`task_id`/`rel_path` 含 `../`、绝对路径、控制字符 → `SecurityError`。
- Local：路径 resolve 后强制在 `<STORAGE_ROOT>/artifacts/_v/` 下（根校验）；S3：IAM 策略仅允许 `artifacts/*` 前缀（部署清单写明，存储层第二重边界）。
- list/GC/对账统一跳过 `_v` 前缀（与 `_tmp` 同模式）。

### 4.5 读取 / 列表 / 对比 API（鉴权闭环同 P5-0）
- `GET /artifacts/{task_id}/{path}` —— 最新（主 key，行为不变）。
- `GET /artifacts/{task_id}/{path}?version=N` —— 历史版本（can_view；不存在 404）。
- `GET /artifacts/{task_id}/{path}/versions` —— 版本列表（⭐2：**分页 + 按 version 倒序 + 返回总数/总字节**；仅 available）。
- `GET /artifacts/{task_id}/{path}/diff?from=N&to=M` —— 行级 diff（🔴6 约束）：
  - 文件大小 > `ARTIFACT_DIFF_MAX_SIZE` → `{status:"too_large"}`，不加载；
  - 二进制 MIME → `{status:"not_text"}`；
  - **流式逐行**对比（不整包进内存）；预览 > `ARTIFACT_DIFF_PREVIEW_LINES` 截断并标注；
  - 返回 `{status, changed, added, removed, preview, truncated}`。
- 全部写 AuditLog（⭐3 细化 action），越权统一 404。

### 4.6 删除与生命周期（🔴5：级联一致）
- `DELETE /artifacts/{task_id}/{path}`：删主 key + 全部 `_v` 版本 + 表记录（失败记审计）。
- `DELETE /artifacts/{task_id}/{path}?version=N`：删单版本；**版本号不重排不补位**，最大版本号恒取表 `max(version)`，不因删除减小。
- **任务级联**：任务删除/过期/归档清理时，同步清理 主产物 + `_v` 版本 + `artifact_versions` 行（沿用 `repos.list_old_tasks` + retention_sweep 扩展；失败记审计）。
- **孤儿巡检**（⭐4 对账，每日）：比对 DB 记录与存储文件——
  - DB 有记录但存储无文件 → 标记并告警；
  - 存储有 `_v` 文件但 DB 无记录 → 清理 + 告警。

### 4.7 审计细化（⭐3）
- action 区分：`artifact_version_archive` / `artifact_version_get` / `artifact_version_diff` / `artifact_version_delete` / `artifact_version_prune` / `artifact_version_reconcile`；
- detail 统一带 `task_id + trace_id + version + operator + result`；失败单独记 `error` 字段便于排查。

### 4.8 指标（⭐6）
- 新增存储指标：`version_total`、`version_archive_ok`、`version_archive_fail`、`version_prune`、`version_bytes`；
- 并入 /metrics `storage` 段；异常（归档失败/对账告警）接入 P4 告警通道。

## 5. 兼容锚点与回滚
- **默认关闭 + 纯透传**（🔴4）：关闭时 VersionManager 直通 backend，无额外分支/捕获/返回值修改；`no_overwrite`/`new` 始终与 P5-0 一致。
- **兼容测试**：关闭开关全量跑通 P5-0 测试集（151 回归），断言返回值、错误码、行为零差异。
- 回滚 = 关开关；`artifact_versions` 表保留不阻塞运行；已归档 `_v` 文件保留，可再开启访问。
- 迁移：新增 `artifact_versions` 表（独立迁移，人工审核，先备份再执行）。
- 存量产物无版本历史不受影响：读最新始终走主 key。

## 6. 测试要点

### 必须覆盖（审查核心用例）
1. **原子性三场景**：归档失败 / 主写失败 / DB 登记失败 → 主版本不受影响、无脏 available、失败记录可被巡检清理。
2. **并发写入**：多协程 overwrite 同一 path → 版本号唯一递增无重复、最终内容 = 最后写入。
3. **路径安全**：`../`、绝对路径、控制字符注入 → SecurityError 拦截，无法越权访问 `_v`。
4. **兼容锚点**：关闭版本管理 → P5-0 全量测试零差异（返回值/错误码/行为）。
5. **幂等收敛**：同内容+同 run_id 不产生新版本；同内容+不同 run_id 产生新版本。
6. **超上限淘汰**：max=3 写 5 次 → 保留 v3..v5，最旧已删（存储+DB 同步）。
7. **级联删除**：删主 key → 版本全清；删单版本 → 版本号不重排、max(version) 正确。
8. **Diff 边界**：二进制 → not_text；大文件 → too_large；越权 → 404。
9. **生命周期**：任务过期 → 主产物+版本+表记录同步清理。
10. **大文件策略**：> `ARTIFACT_VERSION_SIZE_LIMIT` 不自动归档（⭐5）。
11. **审计**：各版本操作 action 区分、带 task_id+trace_id+version；失败带 error。

### 集成验证
- 双后端（Local/S3）版本行为一致性。
- 端到端：Agent 多轮重跑产物 → 版本链正确生成、可回溯、可对比。

## 7. 验收标准
1. 开启版本管理后，同一 path 多次 overwrite 产生递增版本，可回溯任意历史版本；
2. `?version=N` / `versions`（分页+总数） / `diff`（资源约束）三接口鉴权正确、内容真实；
3. 默认关闭时与 P5-0 逐字节一致（纯透传 + 151 零漂移回归）；
4. 版本淘汰、级联删除、生命周期清理、孤儿对账、pending/failed 巡检生效；审计可追溯；
5. Local/S3 双后端行为一致；大文件不归档/不 diff（无 OOM）。

## 8. 风险与回滚增强

| 新增风险 | 影响 | 应对 / 回滚 |
| --- | --- | --- |
| 双系统不一致 | 孤儿数据 / 版本丢失 | 状态机 pending/available/failed + 巡检清理 + 每日对账 + 告警 |
| 并发版本冲突 | 版本号重复 / 内容覆盖 | (task_id,rel_path) 行级排他锁 + DB 原子递增 + 归档带版本号 |
| 版本链膨胀 | 空间快速增长 | 上限淘汰 + 大文件不归档 + 生命周期清理 + 用量告警 |
| 大文件归档/diff 阻塞 | 任务耗时/内存 OOM | 大小阈值（2MB）不归档 / too_large + 流式逐行 diff |
| 删除中间版本语义 | 链缺口 | 版本号不重排，max(version) 取表最大值 |
| 迁移新增表 | 升级失败 | 独立迁移 + 人工审核 + 执行前备份 |
| 关闭态性能回归 | 微秒级 | 纯透传（无包装开销）+ 兼容回归锚 |

> **回滚兜底**：关闭 `ARTIFACT_VERSIONS_ENABLED` 即完全回退 P5-0 行为；`artifact_versions` 表保留不影响运行；已归档 `_v` 文件保留，重新开启可访问。

## 9. 遗留（后续迭代，✨ 项）
1. **版本回滚**：指定历史版本设为当前主版本（自动产生新版本记录，不覆盖历史）。
2. **版本标签/备注**：`stable`/`reviewed` 等标签 + 修改说明。
3. **语义级 diff**：代码 AST / JSON 结构化对比，超越行级。
4. **任务级配额**：按任务/用户配置最大版本数、总存储配额，超量告警。
5. **异步归档**：大文件后台异步归档，主 key 先写入，不阻塞任务执行。
6. **批量对比**：两版本间全量产物差异清单。
7. **压缩存储**：历史版本自动压缩降占用。
