# P3 施工规划：多 worker 扩展 + 监控告警 + 多用户权限 + 前端任务路由

## Context（为什么做）

P2 已交付**单 worker + 单 API 实例**的持久任务队列（ARQ + 断点恢复 + lease + DAG + 前端任务工作台），并完成最高强度审查的 🔴 项修复。P2 审查总结报告明确了 P3 遗留：多 worker 水平扩展、队列监控/告警、多用户/权限、前端任务导航。用户选择**一次性全量实现**四方向。

本 P3 释放 P2 的单 worker/单 API 限制、补可观测与多租户隔离、完善前端作为"可面试演示产品"。项目面向 agent 开发岗位面试，追求分布式技术深度与工程完整。

**兼容锚点（审查星）**：一切向后兼容以 `AUTH_ENABLED`（默认 False）与既有 `USE_QUEUE` 开关为锚——关闭时行为与 P2 完全一致，可平滑回滚。

## 最高强度审查修订落地（2026-09-15，纳入全部 🔴/⭐ 项）

### 🔴 全局架构
1. **长任务 lease 循环续期**：AgentRunner 内起周期续期协程（`lease_ttl/3` 周期）持续刷新 `expire_at`；任务正常结束/失败主动释放 lease；死任务扫描仅处理 `running` 且**带已过期 lease** 的节点（lease 缺失且超时由 updated_at 兜底）——避免多 worker 将执行中的长任务误判重跑。
2. **死任务扫描（resume_inflight）分布式锁**：用 Redis `SET NX EX` 分布式锁保证同一时刻仅一个实例执行全局扫描；扫描周期配置（默认为 lease TTL 的 1/2）；扫描动作写 AuditLog 带 `worker_id` 可追溯。
3. **羊群效应缓解**：`ARQ_MAX_JOBS` 限制每 worker 并发；`claim_node` 失败即退避（不自旋）；数据库连接池按 worker 规模配比（`pool_size` 配置化）。
4. **事件全局顺序性友好的双序号**：事件带全局递增 `gseq` + 任务内 `seq`；前端按 seq 排序、过期丢弃；重复投递对同一连接幂等（前端已按 seq 去重）。
5. **事件 payload 强制携带 `owner_id`**：API 实例收到事件后按本地连接 user_id 匹配过滤再推送（否则实例无法判断 owner）。
6. **恢复扫描只处理 running**：`queued` 任务保留在 ARQ 队列（ARQ 持久化重启保留），不重复入队；仅 `running` 死任务重置入队。
7. **兼容回归基准**：`AUTH_ENABLED=False` + `USE_QUEUE=False` 双关闭跑通 P2 全量测试集零漂移（作为 CI 回归锚）。

### 🔴 P3-1 增补
- 事件广播顺序/去重、owner_id 携带（同全局 4/5）；恢复只 running（同 6）。

### 🔴 P3-2 增补
1. **指标缓存采集**：后台定时（默认 30s）采集写入内存/Redis 缓存，`/metrics` 返回缓存值，杜绝高频查库打挂存储。
2. **告警恢复事件**：指标从告警区回到正常 → 写恢复 AuditLog（`operator=alert-resolve`），冷却期同样适用。
3. **健康分级**：`/health` 返回 `{status: healthy|degraded|unhealthy}`——DB 挂→unhealthy；仅 Redis 挂→degraded（核心可用）。

### 🔴 P3-3 增补
1. **WS 认证用连接后认证帧**：连接建立后先发 `auth` 消息携带 token，服务端校验通过才激活推送；失败回错误码并 `close(1008)`。query `?token=` 仅作兜底并标注风险。
2. **写操作 owner 校验**：advance / 提交决策 / 删除等全部校验 `task.owner_id==user.id`，越权 403；P3 无管理员则一律严格校验。
3. **历史无主任务归属**：开启鉴权时自动把 `owner_id=NULL` 任务归属到内置 `system` 账号；普通用户不可见。
4. **token 生命周期**：多 token 并存、可单独登出撤销；改密后该用户全部历史 token 失效；到期不自动续期（前端 401 跳登录）。
5. **密码强度**：`pbkdf2_hmac_sha256` 迭代 ≥100000、盐 16 字节；`REGISTRATION_ENABLED` 默认 False（关闭公开注册）。
- ⭐ 登录失败限流、全量操作审计（user_id+IP）、token 前缀 `zwt_`。

### 🔴 P3-4 增补
1. **订阅先于拉取**：进详情页顺序 = 建 WS → 订阅当前任务 → GET 全量 → 合并本地，无事件缝隙。
2. **路由鉴权守卫**：无 token 跳登录；接口 401 统一跳登录并清缓存。
3. **全局单例 WS**：单个 WS 连接按 task 分发事件；页面销毁取消订阅；空闲超时关闭防泄漏。
- ⭐ 列表分页、加载/错误/空状态统一、登出清态。

### 测试策略补充（🔴）
并发幂等、长任务 lease 不误杀、死任务恢复接管、越权 read/write、WS 鉴权拒绝、`AUTH_ENABLED=False` 全量回归、事件乱序一致、告警冷却+恢复；⭐ 双 worker+双 API 冒烟、故障注入（kill worker/断 Redis/断 DB）。

### 风险/回滚补充（🔴）

## 分阶段实施（依赖顺序：多 worker → 监控 → 权限 → 前端路由）

### P3-1 多 worker 水平扩展 + 多 API 实例广播
- **目标**：多 arq worker 并行消费；多 API 实例共享事件通道，各实例连接实时收到事件。
- 现有正确性已成立，**无需改认领/广播协议**：
  - `claim_node` 乐观锁（`UPDATE...WHERE status='queued'`）已保证并发安全（`test_claim_idempotent`）；
  - 多实例巡检用 `_job_id=task_id` ARQ 去重，重复巡检无害；
  - 事件广播天然多实例：各 API 订阅同一 `zw:tasks`，只 push 给本地 `_task_ws[task_id]` 连接——连接集互斥 → 每连接恰收一份。
- **改动**：`WORKER_ID` 空值启动自生成 `zw-worker-<suffix>`（每进程唯一，lease/审计可溯源）；`ARQ_MAX_JOBS`（默认 4）→ `WorkerSettings.max_jobs`；`docker-compose.workplace.yml` 加 `api`（`uvicorn --workers 2` 模拟多实例）+ `worker`（`--scale 3`）服务；Makefile 多 worker/多 API 目标。
- **完成标准**：两实例浏览器对同一任务同时收到节点事件；提交多任务后 `worker_id` 分布多值且全完成；并发认领单测通过。

### P3-2 队列监控 / 指标 / 告警
- **目标**：`/health` 扩实时指标、`/metrics` 采集快照、阈值告警（自容，无外部渠道）。
- 新增 `app/observability/`：`metrics.py`（Redis + DB 采集）、`alerts.py`（阈值扫描→写 AuditLog `operator="alert"` + Redis cooldown 防刷屏）、`worker_heartbeat.py`（worker 心跳写 `zw:workers:{id}`，TTL 90s）。
- 指标清单（DB/AuditLog/Redis）：任务吞吐、队列长度（queued 节点数 + Redis `LLEN arq:zeffy`）、节点失败率、活跃 worker 数（`SCAN zw:workers:*`）、处置延迟（queued_at→running 差值）。
- 不引 prometheus-client 等重依赖；`/metrics` 输出 JSON 自描述对象。
- **完成标准**：`/health` 返回新字段；2 worker 时 `active_workers≥2`；制造滞留 queued 超阈值后 `/metrics` 上升且 AuditLog 出现 `alert` 行（冷却期内不重复）；单测用 fake redis。

### P3-3 多用户 / 权限体系
- **目标**：注册/登录/发 token；Task 归属 owner；HTTP + WS 双层鉴权 + owner 过滤。
- 模型+迁移：新增 `users`（id/email(unique)/username/password_hash）、`user_tokens`（id/user_id/token_hash(sha256)/expires_at）、`tasks.owner_id`（FK nullable）；upgrade 建 `system` 种子用户回填已有任务。
- 认证：标准库 `pbkdf2_hmac`+盐+`hmac.compare_digest` 密码；`secrets.token_hex(32)` opaque token，DB 存哈希、可撤销、`AUTH_TOKEN_TTL_SECONDS` 控制；不引 JWT。
- 鉴权：`get_current_user` 依赖（`Authorization: Bearer` / `X-Token`）；`AUTH_ENABLED=False` 时返回匿名 user、owner 过滤短路 → P2 行为不变。
- owner 过滤：`create_task` 写 `owner_id`；`list_tasks/get_task/list_nodes/advance` 按 owner（`owner_id=user.id` 或 `IS NULL` 兼容历史）。
- WS：连接读 query `?token=`，校验失败 `close(1008)`；`_task_ws` 连接记 `ws→user_id`；`task_event_handler` 只推 owner 匹配连接；WS 建任务写 owner。
- **完成标准**：A 用户见不到 B 任务；未带 token 401；WS 只推有权限连接；`AUTH_ENABLED=False` 回归通过。

### P3-4 前端任务路由
- **目标**：登录页 + 任务列表页 + 任务详情页（进入即按 DB 重建节点/审批/追问卡/产物）。
- 极简 hash 路由 `useHashRoute`（`#/login`、`#/`、`#/tasks/:id`），不引 react-router（克制）。`App.tsx` 变路由壳 + 认证态；`useZeffyWs` 增可选 `token`（WS query `?token=`）与 `taskId`（只处理本 task 事件；不加参则旧行为不变）。
- 复用 P2 的 `NodeStrip/ApprovalCard/AskCard/reconcile` 逻辑下移到 `TaskDetailPage`；进页 `GET /tasks/:id/nodes` 对账重建。
- `client/` 新增 `pages/LoginPage|TaskListPage|TaskDetailPage`、`lib/router.ts`、`auth.ts`（token 存取 localStorage + API 封装）。
- **完成标准**：`tsc -b && vite build` 通过；登录→列表→详情闭环；刷新详情页可从 DB 重建卡与产物。

## 风险与回滚
- **向后兼容锚**：`AUTH_ENABLED`（默认 False）+ 既有 `USE_QUEUE`。回滚=改配置不动代码。
- **迁移回滚**：P3-3 `downgrade` = drop `user_tokens/users` + `tasks.owner_id`；`alembic downgrade -1`。
- **多 worker 并发**：LLM 429 由既存 `LLM_MAX_CONCURRENCY` 信号量兜底；并发过高调低 `ARQ_MAX_JOBS`。
- **WORKER_ID 自生成**：本地仍可 `WORKER_ID=zw-worker` 显式覆盖；新增实例用随机后缀不与老值混淆。
- **心跳残留**：TTL 90s 自动过期，不长期误报。
- **前端最小改动**：`useZeffyWs` 只增可选参数，旧连法不变；路由改造只动 App + 抽三页面；`tsc -b` 守回归。
