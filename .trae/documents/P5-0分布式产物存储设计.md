# P5-0 分布式产物存储 · 设计文档（究极深度审查修订版）

> 状态：**最高强度深度审查后修订**。已采纳全部 5 项 🔴 必须修改 + 全部 6 项 ⭐ 强烈建议；✨ 可选优化记入「P5 后续迭代」。未修正会出现的生产级问题（产物覆盖、越权访问、任务失败、存量数据失联、脏数据堆积）已在此版闭环。
> 解决 P4 遗留 #1：跨机器部署下 fs 产物在 worker 本地盘，其他节点/API/前端不可读。

## 1. Context 与目标

现 fs 工具（`app/tools/fs.py`）把产物写 `<WORKSPACE_ROOT>/task-<task_id>/<path>` **本地磁盘**。单机 OK；P4-1 集群化后，产物在执行 worker 本地，API/前端/其他 worker 读不到 →「产物失联」。P5 把文件后端抽象为**统一可寻址对象存储**，写返回统一 key/URL，跨节点/前端可读。

**目标**：
- 产物后端可插拔：本地磁盘（默认，兼容 P4）‖ S3/MinIO 兼容对象存储（可选）。
- 提供跨节点/前端读取的鉴权 API（`GET /artifacts/...`）。
- 兼容锚点：无存储配置时行为与 P4 **零漂移**（协议向下兼容 + 存量产物可读）。

## 2. 现状锚点（已核对 fs.py / models.py / config.py / main.py）
- 写：`_write_file` 原子「临时文件+rename」→ 本地 `task-<id>/<path>`，返回 `{path, abs_path, mode, bytes}`。
- 读/列：`_read_file` `_list_dir` 读本地；权限：`safe_resolve_workspace_path` 防逃逸。
- 写模式 `overwrite / no_overwrite / new(+run_id)` 幂等。
- `TaskNode.output`（JSON 可空）可承载产物元数据；`/health` 已支持 healthy/degraded/unhealthy 分级；`permissions.can_view/can_edit` 可复用；API 分路由模式已建立。
- 调用链：`make_fs_tools(WORKSPACE_ROOT)` → worker/API 各进程各持本地根。**`app/storage/` 尚不存在，P5 从零新建。**

## 3. 方案选型（克制，不魔改 Agent）

引入 `app/storage/` **后端抽象**，代理 fs 工具的文件 IO；**只改 fs 工具的 IO 目标，不改 Agent / 工具入参协议**。
```
StorageBackend
  put(key, data, mode='overwrite') -> ArtifactMeta        # 三种幂等模式统一契约
  get(key)                          -> bytes | None
  stream(key)                       -> AsyncIterator       # 大文件流式读（⭐）
  exists(key)                       -> bool
  delete(key)                       -> bool
  list(prefix)                      -> list[key]
  health()                          -> StorageHealth       # 并入 /health（🔴5）
  ├─ LocalBackend    key → <STORAGE_ROOT>/<key>（本地，默认，含存量兼容映射）
  └─ S3Backend       S3/MinIO 兼容（aiobotocore 可选依赖；未装/未配则不可用）
```
- key 规划：**统一命名空间** `artifacts/{task_id}/{rel_path}`（rel_path 可含 run_id 后缀）。
- `make_fs_tools` 改为注入 `StorageBackend`（经 `app.storage.impl` 全局单例取，配置驱动）。

## 4. 关键设计

### 4.1 后端单例与配置
```
STORAGE_BACKEND: str = "local"          # local | s3
STORAGE_ROOT: str = "./storage"         # local 后端根（可挂共享卷 NFS/EFS 即自然跨机）
ST_ARTIFACT_PUBLIC_BASE: str = ""       # 对象存储直链/预签名前缀（可选；见 4.6 鉴权闭环）
S3_ENDPOINT: str = ""                   # 配了才启用 s3；留空 = local
S3_BUCKET, S3_ACCESS_KEY, S3_SECRET_KEY, S3_REGION
ST_SIGNED_URL_TTL: int = 900            # 预签名 URL 过期秒（默认 15 分钟，🔴4）
ST_RETENTION_FAILED_DAYS: int = 7       # 失败任务产物保留（⭐5）
ST_RETENTION_DONE_DAYS: int = 30        # 完成任务产物保留（⭐5）
ST_GARBAGE_INTERVAL: int = 3600         # 临时文件/过期产物清理周期（🔴5，⭐5）
```
- `STORAGE_BACKEND=local`（默认）→ `LocalBackend`。
- `S3_ENDPOINT` 非空且 `aiobotocore` 已安装 → `S3Backend`；否则启动告警并回退 local。

### 4.2 ~~storage.impl~~ 统一后端接口契约（🔴1 幂等与原子性闭环）

所有后端（含 S3）**必须完整对齐三种写入模式**，Agent 层无感知切换：
- **`overwrite`**：目标存在则覆盖。
- **`no_overwrite`**：目标存在则抛 `FileExistsError`，**不修改原文件**（幂等保护，跨后端一致）。
- **`new`**：自动追加 run_id 后缀生成新 key，**永不覆盖**（文件名规范 `{stem}-{run_id}{ext}` 双后端一致）。

**S3 原子写入兜底**：先写临时 key `artifacts/_tmp/{uuid}` → 成功后 `copy` 到目标 key → 删除临时 key；任一步失败即删除临时 key，**不污染目标路径**，杜绝半截文件。

### 4.3 Key 空间路径逃逸防护（🔴2）

新增统一函数 `normalize_artifact_key(task_id, rel_path)`：
- 强制规范化：解析所有 `../` 并**拦截越界**；绝对路径、空路径、以 `/`/`.`/控制字符开头一律拒绝；
- 最终 key 严格限定为 `artifacts/{task_id}/{rel_path}`，超出该前缀直接抛 `SecurityError`；
- **所有 put/get/stream/exists/delete/list 必须先经此函数校验**，禁止用原始入参拼接 key。
- S3 后端额外限制：IAM 策略仅允许 `s3:PutObject/GetObject/DeleteObject` 于 `arn:aws:s3::{bucket}/artifacts/*`，存储层做第二重边界。

### 4.4 工具协议变更：向下兼容，零漂移（🔴3）

文档此前称「不改协议」不准确。实际为**向下兼容变更**，规则如下：
- `fs_write` 返回字段在**保留旧字段基础上新增新字段**：`{path, abs_path, mode, bytes, exists, key, url}`。
  - **LocalBackend**：`abs_path` 保留本地真实路径（依赖本地路径的逻辑继续可用）；`key=artifacts/{task_id}/{rel_path}`，`url=本地直链（可选空）`。
  - **S3Backend**：`abs_path=None`（无本地概念），`key` 统一、`url` 为可访问地址；依赖 `abs_path` 的逻辑在 S3 下显式不可用，**由 Agent 提示约束**。
- **默认本地模式行为 100% 对齐 P4**（新增字段不影响旧逻辑），Agent 无感知。
- **存量路径兼容映射**：LocalBackend 读时 `task-{id}/<path>` 兼容映射到原 `WORKSPACE_ROOT` 路径；并附**一键迁移脚本** `app/storage/tools/migrate_local.py` 将存量产物迁入新 key 空间（`--dry-run` 预览 → 确认后迁移）。

### 4.5 fs 工具改造
- `fs_write`：校验 → `normalize` → backend.put（按 mode）→ 返回兼容字段。
- `fs_read`：backend.get / stream（大文件走流）。
- `fs_list`：backend.list(prefix=`artifacts/{task_id}`)。
- 逃逸/幂等校验保留（tool 层约束不变）。

### 4.6 跨节点/前端读取（鉴权闭环，🔴4）

- 新增 `app/api/artifacts.py`，全部操作复用 `permissions`：
  - `GET  /artifacts/{task_id}/{path}` —— **读 → can_view**
  - `GET  /artifacts/{task_id}`          —— **列表 → can_view**
  - `DELETE /artifacts/{task_id}/{path}` —— **删 → can_edit**
  - 返回文件流（`StorageFileResponse`）或 302 到 `ARTIFACT_PUBLIC_BASE` **预签名/短时 URL**。
- **预签名 URL 约束**：默认 TTL `ST_SIGNED_URL_TTL=900`（15 分钟）；可选绑定客户端 IP；**禁止生成永久公开链接**；敏感任务（配置项标记）禁止签发预签名、仅走在线流。
- **越权一律 404**：不区分「不存在」与「无权限」，杜绝资源枚举（复用 RBAC 约定）。
- **worker 内部跨节点读取**：worker 属于**可信基础设施**，经 backend 直读（非 HTTP），但**必须经 `normalize` 校验且限本任务 `artifacts/{当前task_id}/` 前缀**，其可访问任务由调度分配（P4 owner 隔离），规避越权。文档明示该安全模型假设。

### 4.7 失败降级与脏数据处理（🔴5）

1. **运行时降级**：S3 写入失败 → 自动降级**重试一次 local**（同 key 写本地，并记审计 `storage_fallback`）；仍失败才标记任务失败。读取：S3 读失败重试一次 + 本地兜底。
2. **临时文件规范**：统一命名 `artifacts/_tmp/{uuid}.part`（S3）与 `<STORAGE_ROOT>/_tmp/*.tmp`（local）；守护协程 `garbage_collector`（周期 `ST_GARBAGE_INTERVAL`）定期清理超过 24h 的临时文件。
3. **存储健康接入 `/health`**：`storage.impl.health()` 结果并入主 `/health`；S3 后端探活失败 → `degraded`（核心可用但产物后端降级），队列巡检感知后**暂缓新任务入队并告警**（复用 P4 notify）。

### 4.8 产物元数据标准化（⭐1）

- 每次 put 记录元数据：`{key, task_id, rel_path, size, mime, created_at, run_id, producer_role, md5, sha256}`。
- 元数据写入 **`TaskNode.output`**（沿用既有字段，无需迁移）；前端 Artifact 列表/审计直接读元数据，不遍历存储。
- 独立性强的用量计量/生命周期，后续可在 P5 深化时加 `artifacts` 元表（本版不阻塞）。

### 4.9 流式读写（⭐2）

- 后端接口支持 `data: bytes | AsyncIterable[bytes]` 双轨；`stream(key)` 读取。
- Local 用文件流（`open(..., 'rb')` 分块）；S3 用分段上传/下载；避免大文件 OOM。

### 4.10 完整性校验（⭐3）

- put 时计算 MD5 + SHA256 随元数据存；get/stream 时校验，损坏抛 `IntegrityError` 并记审计，**不把损坏产物喂给 Agent**。
- S3 端用 `ETag` 做服务端校验（`check_if_modified` 场景）。

### 4.11 全链路可观测性（⭐4）

- 存储指标并入 `app/observability/metrics.py`：存储用量、请求数、成功率、延迟、错误率；按后端 / 任务垂直切分。
- 存储异常触发告警，接 P4 `notify` 通道（指标命中 `NOTIFY_RULES`）。

### 4.12 产物删除与生命周期（⭐5）

- 配套任务删除 / 归档的**产物级联删除接口**（删除走 can_edit）。
- 生命周期自动清理：失败任务产物保留 `ST_RETENTION_FAILED_DAYS`、完成保留 `ST_RETENTION_DONE_DAYS`，过期由 `garbage_collector` 扫描清理，防存储无限膨胀。

### 4.13 审计与 trace
- 产物 put/get/delete/list 记 `AuditLog(action=artifact_put/get/delete/list)`，带 `task_id + trace_id`（沿用 P4）。删除与降级写 `storage_fallback` / `artifact_delete`。

## 5. 兼容锚点与回滚
- `STORAGE_BACKEND=local` + 未配 `S3_ENDPOINT` → **与 P4 完全一致**（本地盘；`abs_path` 保留；存量 `task-<id>/` 兼容映射 + 迁移脚本），零漂移。
- 协议为**向下兼容变更**：只增字段不删旧字段，默认本地行为对齐 P4。
- 回滚 = 改配置回 `local`；`/artifacts` 为新接口，不破坏既有。
- 迁移：无表结构变更（元数据走 `TaskNode.output` + AuditLog）；`artifacts` 独立元表留 P5 深化。
- **共享卷（NFS/EFS）风险明示（⭐6）**：大字号标注——NFS 下 rename 原子性与文件锁/权限在异 OS 不一致、高并发覆盖风险；性能远低于本地盘；大文件/高并发场景**推荐直接 S3**，NFS 仅作小规模跨机兜底，建议关闭并发写。

## 6. 测试要点

### 必须覆盖（核心用例）
1. **路径安全**：`task_id/path` 含 `../`、绝对路径、空、特殊字符 → 断言被 `normalize_artifact_key` 拦截（SecurityError）。
2. **幂等模式一致性**：`overwrite/no_overwrite/new` 在 Local/S3 后端行为完全一致；`no_overwrite` 命中已存在 → FileExistsError 不覆盖。
3. **原子写入**：写入中途失败 → 不留损坏文件、不覆盖原文件（S3 临时 key 清理验证）。
4. **鉴权闭环**：越权访问 404；AUTH off 全放行；预签名 URL 超过 TTL 失效；worker 内部仅限本任务前缀读取。
5. **降级兼容**：S3 不可用 → 自动降级 local 重试一次，任务可正常完成，审计记录 fallback。
6. **存量兼容**：LocalBackend 下 P4 存量 `task-<id>/` 产物可读，零差异；迁移脚本 dry-run/实迁验证。
7. **大文件流式**：MB 级文件流式读写，内存占用无明显飙升。
8. **审计追溯**：所有产物操作写 AuditLog，带 `task_id + trace_id`。

### 集成验证
- 双 worker 跨节点：A 节点写入产物，B 节点经 `/artifacts` 可读。
- 端到端：Agent 执行产出产物 → 前端经 `/artifacts` 下载成功。
- 可选真实 MinIO 冒烟（默认 mock 客户端）。

## 7. 验收标准
1. 产物经统一 backend 写入，返回 key/url（本地模式保留 abs_path）；
2. 任意节点/浏览器经 `GET /artifacts/{task_id}/{path}` 可读，AUTH 鉴权正确（读 can_view / 删 can_edit / 越权 404）；
3. 未配 S3 时全程本地后端，行为与 P4 零漂移（回归全绿 + 存量产物可读）；
4. 配 MinIO/S3 后端后 put/get 正常，三种幂等模式一致，S3 失败自动降级；
5. 存储健康并入 /health，S3 挂返回 degraded；
6. 审计带 task_id+trace_id；生命周期清理生效。

## 8. 风险与回滚增强

| 新增风险 | 影响 | 应对 / 回滚 |
| --- | --- | --- |
| 存量产物升级后失联 | 历史任务产物无法访问 | 存量路径兼容映射 + 一键迁移脚本；升级前全量备份 |
| S3 最终一致性 | 刚写完读不到 | 写入后强一致校验 + 关键路径读后置重试 |
| 预签名 URL 泄露 | 产物未授权访问 | 短有效期（15min）+ 可选 IP 绑定；敏感任务禁签发 |
| 共享卷并发冲突 | 文件损坏、覆盖 | NFS 关闭并发写或直接 S3；风险明示 |
| 存储无限膨胀 | 盘/桶占满 | 生命周期自动清理 + 用量告警 |
| S3 运行中故障 | 任务批量失败 | 自动降级 local 重试一次 + /health degraded + 暂缓入队 + 告警 |

> **兼容锚点重申**：配置切回 `local` 后端即回滚，业务逻辑零改动；已写 S3 的产物保留，可配置切回访问。

## 9. 遗留（P5 后续迭代，✨ 项）
- 产物**版本管理**（N 次写入留历史、回溯、对比）
- 在线**预览**（图片/代码/Markdown/PDF，无需下载）
- **断点续传**大文件（弱网补偿）
- **配额管理**（按用户/团队限额 + 超量告警拦截）
- **CDN 加速**公开产物
- **存储分层**（热标准 / 冷归档低频，降本）
- **事务性写入**（多文件产物原子提交，全成或全回）
- 独立 `artifacts` 元表与用量计量（深化成本/用量统计）

> **最终结论**：5 项 🔴 设计漏洞已全部闭环——存储幂等/原子性统一契约、key 路径逃逸防护、协议向下兼容与存量迁移、鉴权闭环（读/列/删 + 短时预签名 + worker 前缀限制 + 越权 404）、失败降级与脏数据清理（含 /health 接入）。6 项 ⭐ 全部采纳（元数据标准化、流式、完整性、可观测、生命周期、共享卷风险明示）。✨ 7 项记入 P5 迭代。修订版可实现为工程严谨、兼容平滑的分布式存储方案。
