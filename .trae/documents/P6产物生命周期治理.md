# P6 产物生命周期治理 · 设计文档（配额 / 元表·计量 / 事务性写入 / 存储分层）

> 状态：**设计稿，待审查迭代**。
> 实施状态：**核心全部落地**（2026-09-15）。批次 A 三表迁移(artifacts/quota_usage/artifact_tx)、B 元表记录+上传链路接入、C 配额校验/冲正、D 事务批次(governance+API)、E 分层(Local移_cold+S3 StorageClass+冷化守护)、F 计量API(/artifacts/stats)+GC治理联动 均已完成。后端 197 passed + 1 skipped，ruff 全绿。tx/stats API 治理关时 404（兼容锚点）。
> 主题：为 P5 产物存储补齐「从写入到回收」的治理闭环，四个方向共享一个权威 `artifacts` 元数据表作为地基。
> 范围界定（已与用户对齐）：本地私有项目，**不做 CDN 公开加速**；配额按**用户(owner_id)**计算；事务性写入做**批次原子提交**（覆盖 Agent 端到端）；存储分层为**元数据标记 + 真实归档**。
> 原则：**零侵入 + 向后兼容**——`STORAGE_BACKEND=local` 默认行为零漂移；`ARTIFACT_META_ENABLED=false` 时元表不写入、配额/计量/事务/分层全部跳过（兼容锚点）。

---

## 0. 现状诊断（P6 缘起）

| 问题 | 现状 |
|---|---|
| 产物无权威元数据 | 元数据散落 `TaskNode.output`、`artifact_versions`（仅版本化开启时）；GC 靠 `list()` 列举 key 对账，无统一每次写入记录 |
| 无用量统计 | `record()` 仅内存计数（`/metrics`），不持久化、无按用户维度 |
| 无配额 | 无上限，磁盘/桶可无限膨胀 |
| 无事务 | 单文件 `put` 三种幂等模式，多文件无原子提交；任一半成留下脏产物 |
| 无分层 | 无 hot/cold 区分，冷数据占热成本 |

**核心洞察**：四个方向可收敛为「**一个权威元表 + 写入前校验（配额）+ 写入中记录（元表/计量）+ 批量原子化（事务）+ 生命周期标记（分层）」**。

---

## 1. 全局修订（🔴 必须闭环）

| 审查项 | 闭环方案 |
|---|---|
| 🔴1 元表权威性 | 新增 `artifacts` 表**每次**产物写入落一条记录（含 owner_id/size/backend/tier/sha256）；查询/配额/计量/配额校验全部以元表为准，杜绝依赖 `list()` 列举对账 |
| 🔴2 并发一致性 | 元表写入与后端 `put` 需在**同一事务语义**下完成：先写后端（幂等 key 落位）再写元表；元表写入失败则补偿清理后端 key，保证无「有文件无记录/有记录无文件」 |
| 🔴3 配额校验时序 | 校验位于**写入前**（预估 size），写入后以实际 size 回填；超配名并发竞态用「校验+记账原子化」缓解（乐观，非绝对），文档明示边界 |
| 🔴4 事务原子性 | 批次提交：临时 `_tx/` 前缀写多产物 → 全部成功后统一置 available + 建元表 → 任一失败全量清理回滚；不破坏现有单文件 `put` 路径 |
| 🔴5 配额回滚 | 写入失败/删除产物需**冲正**配额占用，避免配额虚高被堵死 |

## 2. 数据模型（DB 变更）

### 2.1 新增 `artifacts` 表（权威元表，🔴1）

```python
class Artifact(Base):
    __tablename__ = "artifacts"
    id: str(36) pk
    task_id: FK(tasks.id, ondelete=CASCADE) index
    rel_path: str(512)
    key: str(512)          # 主 key（当前可用产物）
    version: int           # 关联 artifact_versions.version；0=未启用版本化
    owner_id: FK(users.id, ondelete=SET NULL) index   # 🔴 配额按此维度
    size: int
    backend: str(16)
    tier: str(16) default "hot"     # hot/cold（P6 存储分层）
    sha256: str(64)
    mime: str(128)
    producer_role: str(32)
    status: str(16) default "available"   # available/archived/failed
    tx_id: str(36) index nullable         # 所属事务批次（🔴4）
    created_at: datetime index
    updated_at: datetime
    __table_args__ = UniqueConstraint("task_id", "rel_path", "version", name="uq_artifacts_task_rel_ver")
```

> 与 `artifact_versions` 关系：`artifact_versions` 是版本链（历史归档），`artifacts` 是**当前可用产物快照**。版本化开启时二者同频；关闭时 `artifacts` 独立记录、`version=0`。

### 2.2 新增 `quota_usage` 表（用户配额用量）

```python
class QuotaUsage(Base):
    __tablename__ = "quota_usage"
    owner_id: str(36) pk FK(users.id)
    used_bytes: int default 0       # 当前占用（仅 available+hot 计入；archived/tier=cold 可降权）
    updated_at: datetime
```

> 设计取舍：用量**物化为行**（每次写入 +/- 原子 UPDATE），而非聚合 `artifacts` 求和——避免大表 COUNT/SUM 拉垮查询；`used_bytes` 原子加减保证配额校验与更新一致性。

### 2.3 事务批次表（🔴4）

```python
class ArtifactTx(Base):
    __tablename__ = "artifact_tx"
    id: str(36) pk
    task_id: FK index
    owner_id: FK(users.id)
    status: str(16) default "pending"   # pending/committed/failed/rolled_back
    created_at: datetime
    committed_at: datetime nullable
```

> `artifacts.tx_id` 关联批次；批次 commit / rollback 据此批量更新状态。

### 2.4 alembic 迁移

首版 `P6-0 产物治理建表`：新建 `artifacts`、`quota_usage`、`artifact_tx` 三表。**人工审核迁移脚本**（沿用项目硬约束，不 autogenerate 直跑）。

## 3. 配额管理（按用户）

### 3.1 配置

```ini
QUOTA_ENABLED=false
QUOTA_ASSET_MAX_BYTES=0            # 单产物上限（0=不限制）
QUOTA_TOTAL_MAX_BYTES=0            # 用户总配额（0=不限制）
QUOTA_TIER_COLD_FACTOR=0.1         # cold 归档占用折算系数（可选，降权）
QUOTA_EXEMPT_SYSTEM=true           # system 账号豁免
```

### 3.2 校验时序（🔴3）

写入前（预估）：`check_quota(owner_id, add_bytes)`：
- `QUOTA_TOTAL_MAX_BYTES>0` 且 `used_bytes + add_bytes > max` → 拒绝（400/413）
- 单产物：`QUOTA_ASSET_MAX_BYTES>0` 且 `size > max` → 拒绝

写入后：`bump_quota(owner_id, delta)` 原子回填，并校验实际 size 未超（异常则回滚并冲正）。

### 3.3 冲正（🔴5）

删除产物 / tx rollback / 写入失败 → `-size` 冲正 `used_bytes`（floor 0）。GC 清理归档产物时同步冲正。

### 3.4 冲突处理

- `ARTIFACT_META_ENABLED=false`：无配额（跳过全部）
- moto/local 测试注入小配额验证拦截

## 4. 元表与用量计量

### 4.1 元表写入（🔴1/🔴2）

统一 `record_artifact(session, owner_id, meta, tier, tx_id)`：
- 每次 `put` 成功后调（Agent fs_write / 上传链路 / 事务批次）
- 后端 key 已落 → 写元表；元表写失败 → 补偿删后端 key 并审计（防孤儿）

### 4.2 用量计量 API

- `GET /artifacts/stats` → `{owner_id, total_bytes, hot_bytes, cold_bytes, count, by_tier}`
- `GET /artifacts?owner=<id>` 已支持；补 `tier` 过滤
- `/metrics` 新增 storage 指标：`storage_usage{owner,tier}` 后台定时采集（沿用 P3-2 采集模式）

### 4.3 GC 改造

从「列举 key 对账」改为「以 `artifacts` 元表为准」：扫 available 元数据 → 生命周期（失败 7 天/完成 30 天）→ 删后端 key + 删元表 + 冲正配额。

## 5. 事务性写入（🔴4）

### 5.1 接口

```
POST /artifacts/tx/open        {task_id, owner}            → {tx_id}
PUT  /artifacts/tx/{tx_id}/{rel_path}  body=二进制         → 写临时 _tx key，未置 available
POST /artifacts/tx/{tx_id}/commit                          → 校验全块 → 全部置 available + 建元表 + bump 配额
POST /artifacts/tx/{tx_id}/rollback                        → 清理全部临时 key + 冲正
GET  /artifacts/tx/{tx_id}                                 → 状态/进度（⭐）
```

### 5.2 原子语义

- `open`：无配额预扣（commit 时统一校验）
- 各文件写 `_tx/{tx_id}/{rel_path}`（后端 put，幂等）
- `commit`：一次性校验配额总 size → 逐 file 从 `_tx` copy 到正式 key（`vm.put` 走版本链）→ 全成功则建元表 + bump 配额定状态 committed；中途失败 → 回滚已 copy 的 key，置 rolled_back，不残留半成（🔴4）

### 5.3 双后端一致

Local：`_tx` 临时目录 copy;S3：`_tx` 临时 key + copy_object，均原子（复用 P5 原子写模式）。

### 5.4 Agent 端到端

Agent 一次产出多文件（如结果 + 配图 + 日志）→ 走 tx 批次原子提交，任一半成不污染正式产物空间。

## 6. 存储分层（标记 + 真实归档）

### 6.1 配置

```ini
TIER_ENABLED=false
TIER_COLD_ARCHIVE_AGE=30d        # 超过该年龄自动降 cold（守护协程）
TIER_COLD_DIR=_cold              # Local 冷归档目录
TIER_COLD_S3_CLASS=STANDARD_IA   # S3 冷归档 StorageClass
```

### 6.2 机制

- 写时 `tier=hot`（默认）；`GET /artifacts/{task}/{path}?tier=cold` 或守护按 age 扫描 → 冷归档
- Local：把 `artifacts/{task}/{rel}` **移动到** `artifacts/_cold/{task}/{rel}`，更新 `artifacts.tier=cold`；读时路由区分 hot/cold 目录，对外 key/URL 不变（路由层透明）
- S3：对象 `copy_object` 指定 `StorageClass` 重写，更新 `tier=cold`（S3 原生分层）
- 配额折算：cold 按 `QUOTA_TIER_COLD_FACTOR` 折算占用（可选降权）

### 6.3 生命周期回收

GC 对 `tier=cold` 且超过保留期 → 删除 + 冲正配额（冷数据降本同时不无限堆积）。

## 9. 风险与回滚

| 风险 | 影响 | 应对/回滚 |
|---|---|---|
| 元表一致性（文件与记录漂移） | 计量/配额失真 | 🔴2 补偿删 key；GC 定期对账告警 |
| 配额竞态（并发写同用户） | 峰值微超 | 乐观校验 + 文档明示边界，非强一致 |
| 事务半成污染 | 脏产物 | 🔴4 全回滚；_tx 前缀 + GC 兜底清理 |
| 迁移字段 | 历史数据 | 新增表全 nullable/默认，无破坏；代码回滚零影响（类似 P5 结论） |
| hot 读冷路由 | 路由错配 | tier 更新事务化 + 读时后端统一解析 key 映射 |

**回滚**：`ARTIFACT_META_ENABLED=false` 即退回 P5 行为（元表/配额/事务/分层全跳过，零漂移锚点）。
