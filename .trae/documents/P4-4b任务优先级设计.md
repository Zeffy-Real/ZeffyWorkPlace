# P4-4b 任务优先级 · 设计文档（究极深度审查修订版）

> 状态：**审查修订待确认**。采纳本轮全部 🔴/⭐；✨ 老化/动态池/抢占/时间片/死信/配额 记入 P5。
> 核心结论：仅「worker 池隔离」不能真正解决饥饿——必须叠加「共享资源（LLM 并发）分级配额」与「高优提交权限控制」，否则上线必现「优先级没用 / 低优仍饿死」。

## 1. Context 与目标

P4-4 上补做任务优先级。目标：任务分低/中/高，优先执行高优，同时**确保低优不因 LLM 并发共享而实际饿死**；`ARQ_PRIORITY_ENABLED=false`（默认）行为与 P4/P3 一致（兼容锚点）。顺带修复存量隐患（`ARQ_QUEUE_NAME` 未真正生效 → 指标错表）。

## 2. 方案选型（基于 ARQ 源码验证）

- ARQ 单 worker 只绑定单队列（`self.queue_name`），无跨队列优先级轮询；
- 入队支持 `_queue_name=` 选命名队列；
- 队列为 Redis ZSET（按入队时间，同队列天然 FIFO）。

⟹ **分级命名队列 + 分级 worker 池 + 分级 LLM 配额**：
队列 `zeffy_hi / zeffy(中) / zeffy_lo`；入队按 `task.priority` 选命名空间（全链路）；worker 分别绑定各级队列并按比例配置数量（资源倾斜高优）；同时 LLM 并发信号量拆分级配额，保证低优最小执行资源。

> 不采用：魔改 ARQ 单进程多队列轮询（侵入框架）；单队列持久化优先级排序（需自写公平调度，违背克制）。

## 3. 🔴 5 项 P0 闭环（审查全部纳入）

### 3.1 共享资源分級配额（LLM 并发）——饥饿的真正闭环
- 全局 LLM 信号量由「单一共享」改为 **per-priority 分级配额 + 公共池**：
  - 总并发 `LLM_MAX_CONCURRENCY` 拆为 `hi/mid/lo` + `public`；
  - 默认 `hi=5 / mid=3 / lo=2 / public = 总-10`（可配置）；
  - **低优保底**：`lo` 配额不对外出借，高优满额时只借 `public`，**不得占用 lo 保底**；
  - 高优满时借 `public` 提升利用率。
- Agent 调用 LLM 的 acquire 需带**当前任务优先级**，据此选对应配额信号量（`get_llm_semaphore(priority)`）。
- 配套校验：`每个 worker 的 ARQ_MAX_JOBS × 分级 worker 数 ≤ 对应分级配额 + public`（防 worker 空转、任务堆在 worker 内部）。
- 文档明示：**worker 池独立 ≠ 饥饿已解，必须配合 LLM 分级配额**。

### 3.2 高优提交权限控制（防空占用）
- 绑定 RBAC：**仅 admin（role=admin/system）可提交 `priority=2`**；普通用户提交高优 → 403。
- 普通用户仅 `0/1`（低/中）。
- `POST /tasks`（与 WS 建任务）校验滚动：普通用户超限直接 403。
- 预留配额：单用户/单日高优惠额度留 P5，P4 先做权限拦截。

### 3.3 开关切换残留处理（防任务滞留）
- **关闭策略（默认）**：停止接收新分级任务（新任务入 `<base>`）；已入 `_hi/_lo` 的任务由对应分级 worker **继续消费完毕**，worker 自然空闲后停止。
- **可选管理命令**：`repriority 迁移` 可将 `_hi/_lo` 剩余任务批量迁回 `<base>`（彻底关闭分级用）。
- **禁止行为**：关闭后不得直接 kill 分级 worker（否则残留任务永久丢失）。

### 3.4 DAG 优先级继承
- 规则：**同一任务所有 TaskNode 统一继承任务级优先级**，全链路入队（首节点/后续/重试/resume/回退重入队）都用 `task.priority` 选命名空间，DAG 内部不重新定级、不升降级。

### 3.5 队列命名全链路对齐（修 bug 且功能无盲区）
- 收敛为单一 helper：`queue_for(priority, enabled)` / `all_queue_names()`；
- **全模块对齐**：入队（gateway）、恢复巡检（recovery）、API 侧 sweeper 补入队、死任务扫描重入队、lease/审计/告警中涉及队列长度的指标、监控指标 `queue_redis_len`（LLEN 聚合 `arq:<base>[_hi/_lo]`），统一走该 helper，杜绝错表/错位。

## 4. 公平性与局限
- 保底配额（3.1）+ 专属 lo worker（2）→ 低优不饿死（除非 lo 保底被超长高优洪峰+lo 容量耗尽，属容量受限而非阶梯饿死）。
- 同优先级内严格 FIFO（ARQ ZSET 按时间，原生保证）。
- **局限（如实写明）**：低优容量受限时变慢；不做优先级老化/抢占/时间片/配额——留 P5。

## 5. 数据库变更
- `tasks.priority int not null default 1 index`（0 low/1 mid/2 high）。迁移 `<rev>_p4_priority.py`，降级删列（非破坏性）。

## 6. 配置与环境变量
```
ARQ_PRIORITY_ENABLED: bool = False       # 锚点：关=单队列（P4 行为）
ARQ_QUEUE_NAME: str = "zeffy"            # 基队列名（本方案真正接线)
LLM_MAX_CONCURRENCY: int = 32            # 总并发（拆分成配额）
LLM_QUOTA_HI: int = 5
LLM_QUOTA_MID: int = 3
LLM_QUOTA_LO: int = 2
LLM_QUOTA_PUBLIC: int = 8                # 其余入 public；高优满时借用
ARQ_PRIORITY_WORKERS: dict = {"hi":2,"mid":1,"lo":1}   # 部署用
LLM_QUOTA_PUBLIC: int = 0                # 0 = 总 - (hi+mid+lo)，默认
```

## 7. 代码改动点
**模型/迁移**：`models.Task.priority`；迁移。

**资源配额**：`appstate.get_llm_semaphore(priority=None)` → 返回 per-priority 信号量；提供 `_pick_llm_pool(priority)`（hi→hi,借public；mid→mid,借public；lo→lo 仅保底）。`LLM_MAX_CONCURRENCY` 拆分初始化。

**优先级代理**：`queue/priorities.py`：`queue_for(priority, enabled)`、`namespace_metric()`。全模块复用。

**入队**：`gateway.enqueue_task/enqueue_resume`、`recovery.resume_inflight`、`appstate._sweeper` 均按 `task.priority` 带 `_queue_name`。

**权限**：`main.create_task_endpoint`（及 WS 建任务）校验普通用户 priority>1 → 403。

**worker/quota**：WorkerSettings 读 `ARQ_QUEUE_NAME`（+ `_hi/_lo` 按启动参数绑定）；`make_worker_settings(queue)` 或 env 注入 `ARQ_QUEUE_NAME=zeffy_hi` 启动对应 worker；`ARQ_MAX_JOBS×worker数 ≤ 配额` 断言（启动时校验）。

**指标**：`metrics.queue_redis_len` 改聚合 `arq:<base>[_hi/_lo]`；⭐分队列独立统计（长度/平均等待/失败率）+ 独立告警阈值（hi 积压→high，lo→warning），接入 notify。

**审计（⭐）**：任务优先级变更 / 高优提交 / 调级，写 AuditLog（提交者 user_id、优先级、时间）；支持按用户统计高优占比。

**admin 调级（⭐）**：`/admin/tasks/{id}/priority`（仅 admin）设置新优先级并重入对应队列，审计留痕。

## 8. 兼容锚点与回滚
- 关 `ARQ_PRIORITY_ENABLED`：全部入 `<base>`、单一 worker、单一（总并发）信号量、无权限限制（优先级字段保留不影响）→ P4 行为；**普通用户 priority 参数被忽略/置中**。
- 残留：按 3.3 默认关闭策略（分级 worker 消费完毕）+ 可选迁移命令。
- 回滚均为配置级，无破坏性迁移。

## 9. 测试要点（强化用例全覆盖）
1. **资源抢占保底**：高优打满 LLM 配额时，低优仍获执行进度（保底 lo 生效）；
2. **权限**：普通用户 priority=2 → 403；admin → 200；
3. **开关切换全流程**：开→提交分级→关→残留消费完+新任务入默认→再开，无丢失；
4. **DAG 继承**：多节点任务所有节点入队命名空间 = 任务优先级；
5. **同队列 FIFO**：同优先级按入队顺序；
6. **洪峰稳定**：全量高优涌入，低优仍有进展、无死锁；
7. **恢复一致性**：重启后回放优先级与队列正确；
8. **指标/审计**：queue_redis_len 聚合正确；优先级变更审计落库。
- 集成：3 队列+3 worker 池，高优平均完成时间<中<低；长时间运行低优最终全部完成。

## 10. 验收标准
1. `ARQ_PRIORITY_ENABLED=true` 下高/中/低任务分布到正确队列；
2. admin 可提高优、普通用户 403；DAG 节点继承；
3. 高优打满 LLM 时低优仍保底推进（不饿死）；
4. 关闭开关 = P4 零漂移 + 残留任务消费完毕；
5. `queue_redis_len` 修复后准确；分队列独立指标+告警+审计生效；
6. 前后端测试/构建全绿。

## 11. 风险与回滚
| 风险 | 影响 | 应对/回滚 |
|---|---|---|
| 全员高优 | 体系退化单队列 | 权限拦截 + 高优占比告警 |
| LLM 共享抢占、低优真饿死 | 低优永久排队 | 分级配额+保底（3.1）+ 低优等待监控 |
| 开关残留滞留 | 任务不执行 | 残留策略（3.3）+ 迁移命令 |
| 优先级滥用 | 高优被无谓占用 | 全量审计 + 定期清理 |
| 多队列指标错 | 监控失效 | 全链路队列名 helper 对齐 |

> 回滚兜底：关 `ARQ_PRIORITY_ENABLED` 即回单队列；已入分级队列任务按残留策略处理，不丢失、不重复。
