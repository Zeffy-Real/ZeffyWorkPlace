## 1. Context 与目标

P5-0/1/2 已交付 /artifacts 读取、版本、在线预览。当前 `GET /artifacts/{task_id}/{path}` **全量流式返回**（单次 200），无 HTTP Range。弱网/大文件下载中断后需从头重拉。断点续传解决：**中断后从已接收字节续传**。

**目标**：
- 后端标准 Range：`GET` 支持 `Range: bytes=start-end` → 206 + `Content-Range`；`HEAD` 返回 `Content-Length`/`Accept-Ranges`/`ETag`。
- 前端分块续传：弱网中断后从断点续拉；预览大文件流式首屏。
- 兼容锚点：**无 Range 头时行为与 P5-0 完全一致**（单次 200 全量），零漂移。

## 2. 现状锚点（已核对 base/local/s3/versioning/artifacts）
- `stream(key)`：全量迭代（local 从 0 读；s3 `get_object` 无 Range）。**无 offset 参数**。
- `get(key)`：全量 bytes，无 size 反射。
- `/artifacts` GET：`_stream()` 全量 yield，默认 200；无 HEAD；无 Range/Content-Range/Accept-Ranges/ETag。
- 前端 `artifactBlob`：单次 `res.blob()`；预览 `blob.slice` 读首部（依赖单次全量 fetch）。

## 3. 方案选型（标准 HTTP Range，不引入依赖）

后端标准 Range + 前端分块续传器。**放弃**第三方断点库（克制）。

## 4. 关键设计

### 4.1 并发文件句柄安全（🔴1）
- **强制约束**：每次 `stream` 调用**独立打开本地文件句柄**，交给 async generator 的 `with` 语句在迭代结束后自动关闭；**禁止全局/共享句柄**（`local.py` 当前已是 `with target.open()`，天然独立——保留并单测确认）。
- `stream(key, start)`：入口 `seek(start)` 前校验；seek 失败抛 `RangeNotSatisfiableError`。
- **并发单测**：多协程同时请求同一文件不同区间，断言各自返回内容与对应字节区间完全一致（防共享句柄错位）。
- S3：每次 `get_object(Range=...)` 独立，无此问题——但错误码/降级策略须与 Local **严格对齐**（双后端一致性）。

### 4.2 文件一致性校验：ETag（🔴2）
- 后端 `HEAD` 与 `GET` 统一返回 **`ETag`**（基于内容哈希或 `(size, mtime)` 生成；local 用 `size + mtime_ns`，S3 用 `ETag` 头）。
- 前端首次请求记录 ETag；**续传前校验不一致 → 丢弃已接收数据，自动从头下载**。
- **跨版本禁止续传**：`?version=N` 的 Range 请求，前端版本切换强制清空断点缓存。
- 文件大小变更 → 判定失效重置。

### 4.3 边界与非法输入防护（🔴3）
- `StorageBackend.stream` 入口强制校验：`start` 必须**非负整数**（负数/浮点抛 `RangeNotSatisfiableError`）；`start ≥ size` → 抛 `RangeNotSatisfiableError`。
- 非法 Range 格式（多段、后缀 `bytes=-N`、非数字）统一处理：**降级返回 200 全量**。
- `size(key)`：local `os.stat` / S3 `head_object`；拿不到 size → 忽略 Range 走 200（降级零风险）。
- 双后端错误码、降级策略完全一致（单测双后端对齐）。

### 4.4 前端内存上限与熔断（🔴4）
- 最大续传大小阈值 `RANGE_MAX_SIZE`（默认 **50MB**）——超过降级普通全量下载，提示「文件过大，不支持断点续传」。
- 每 chunk 后校验内存累计，超阈值主动终止、释放、回退全量。
- **明确**：内存续传仅适合中小文件与预览首屏；超大文件走浏览器原生下载。

### 4.5 分块完整性校验（🔴5）
- 每块接收后按 `Content-Range` 校验起止位置与长度，**长度不匹配 → 重试该块**。
- 整文件完成校验总大小 == `Content-Length`，不一致则整体重试或报错。
- 重试超限抛可续传错误，保留已接收字节。

### 4.6 串行分块 + 进度标准化（⭐1/2）
- 前端分块**串行执行**（同一时间仅一个块在途）；预示并发配置位，默认 `RANGE_MAX_CONCURRENCY=1`。
- `onProgress` 返回 `{ received, total, percent, speed }`（已接收/总量/百分比/瞬时速度），预览与下载复用。

### 4.7 HEAD 与 GET 头对齐 + 小文件跳过（⭐3/4）
- HEAD 返回与 GET 完全一致头：`Content-Type`/`Content-Length`/`Accept-Ranges`/`ETag`/`Last-Modified`。
- **小文件优化**：文件 < `chunkSize` → 直接 200 全量，不处理 Range（省 stat/seek）；前端 < 阈值单次 fetch，不发 HEAD。

### 4.8 错误分级与重试策略（⭐5）
- 网络/超时 → 指数退避重试（默认 3 次）；
- 416 → 断点失效，自动从头；
- 401/403/404 → 立即终止，触发权限/登出；
- 全部错误写前端日志。

### 4.9 版本管理兼容（⭐6）
- `?version=N` + Range → 定位对应历史版本文件片段（versioning 透传 stream(start)）。
- 版本切换自动清空断点缓存，不跨版本续传。

## 5. 兼容锚点与回滚
- **无 Range 头 / 无 Accept-Ranges** → 后端 200 全量、前端单次 fetch，**与 P5-0 逐字节一致**（167 回归 + 预览/下载冒烟）。
- HEAD 新路由、Range 增量能力，旧客户端不受影响。
- 回滚 = 前端降级单次 fetch（`fetchResumable` 自动检测）；后端 Range 逻辑对无 Range 请求零影响；**可通过配置全局关闭 Range 能力**（零代码回滚）。
- 无表结构/依赖变更。

## 6. 测试要点
1. **并发安全**：多协程请求同一文件不同区间 → 返回与字节区间完全对应，无错位（Local/S3）。
2. **文件变更续传**：下载中改文件 → ETag 不一致 → 自动重置从头。
3. **边界输入**：`start=0`/`start=size-1`/`start=size`/`start=-1`/浮点 → 正确 206 或 416 或降级。
4. **非法 Range**：多段、后缀、非数字 → 降级 200 或 416。
5. **内存保护**：> 50MB → 降级全量，不启用分块续传。
6. **续传完整性**：模拟中断后续传 → 校验和与原文件一致。
7. **鉴权一致性**：HEAD/Range 越权 404、未授权 401，与 GET 一致。
8. **兼容锚点**：无 Range → 行为/头/错误码与 P5-0 零差异（167）。
9. **版本兼容**：`?version=N` + Range → 对应历史版本片段。

### 集成验证
- 真实大文件 + 弱网限速（Playwright route 模拟）中断后续传完整。
- Local / S3 双后端一致；预览首屏流式明显快于全量。

## 7. 验收标准
1. `Range` 请求返回 206 + 正确 `Content-Range`，可从头/中间续传；
2. `HEAD` 返回 size + Accept-Ranges + ETag；
3. 前端大文件下载中断→续传成功，进度可感知；
4. 预览大文本仅拉首屏（Range），不整包进内存；
5. 文件变更/版本切换自动重置断点（ETag 校验）；
6. 无 Range / 无 Accept-Ranges 时与 P5-0 完全一致（零漂移回归）；
7. 内存 >50MB 降级全量，无 OOM；后端 167 零漂移、前端 build 通过。

## 8. 风险与回滚增强

| 新增风险 | 影响 | 应对 / 回滚 |
| --- | --- | --- |
| 并发 seek 数据错位 | 文件损坏 | 独立句柄 + 并发测试；问题则全局关闭 Range |
| 文件变更续传损坏 | 产物不可用 | ETag 校验 + 不一致自动重置 |
| 大文件内存暴涨 | 标签页崩溃 | 50MB 阈值 + 内存熔断，降级全量 |
| Range 解析异常 | 500 | 严格入参校验 + 非法降级 200 |
| 频繁小文件 Range 开销 | 服务端性能 | 小文件跳过 Range |
| ETag 跨代理不一致 | 误重置 | ETag 基于内容/强校验；无则降级单次 |

> **回滚兜底**：`RANGE_ENABLED=false` 配置全局关闭（后端对无 Range 行为不变）；前端无 Accept-Ranges 自动降级单次 fetch。无表结构/依赖变更。
