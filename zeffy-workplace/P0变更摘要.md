## 七、P0 关键设计决策（P1 理解"为什么这么做"，避免推翻预埋）

| 决策 | 选择 | 理由 | 约束/代价（P1 注意） |
|---|---|---|---|
| 建表 | `metadata.create_all`，不用 alembic | P0 最小脚手架 | P1 必须切 alembic；改模型须手动清 PG volume |
| WS 会话 | 内存 `_active_connections` 单实例 | 快速跑通链路 | 不能多实例；P1 迁 Redis Pub/Sub |
| 用户体系 | 单用户本地、无鉴权 | 减少 MVP 复杂度 | P2 才引入多用户/权限 |
| LLMClient | 仅预埋 `usage` 签名，真实统计 P1 做 | P0 聚焦调用链路 | P1 需回填 usage_metadata |
| Qdrant | 配置就绪，P0 不启动 | 减资源占用 | P1 启 vector compose 接入记忆 |
| 后台任务 | P0 无；WS 同步 echo | echo 瞬时无阻塞 | ⚠️ P1 Agent 长任务必须移出 WS 协程 |

## 八、P1 风险警示（P0 代码无 bug，P1 前置强制注意）

1. **uvicorn 强制 `--workers 1`**：只要还用内存 `_active_connections`，多 worker 会导致不同进程消息分发失效。迁移 Redis Pub/Sub 后才支持多 worker。
2. **create_all 致命限制**：P0 改 `models.py` 必须 `docker compose -f docker-compose.base.yml down -v` 清 volume，否则新增字段不生效 → ORM 缺列报错。P1 第一件事接入 alembic 废弃 create_all。
3. **Agent 文件操作强制走 `safe_resolve_workspace_path`**：P1 写工具插件时禁止直接拼接路径，所有读写必须调该函数，防目录穿越。
4. **WS 协程禁止执行长耗时 Agent 逻辑**：ASGI 服务器对 WS 有超时；Agent 推理/工具调用几十秒~几分钟，绝不能放在 `ws.py` 回调协程内，必须投递任务队列，WS 只负责消息接收与状态推送。
